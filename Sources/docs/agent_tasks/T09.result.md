## What changed

- **`backend/app/rag/snapshot.py` (new):**
  - turns snapshot rows into ParsedDocuments, with English-only headers;
  - strips the Seoul `/ … /` title wrapper (the original title goes to `title_original`);
  - cuts sections at a span boundary before 320 tokens;
  - `SpanLookup` gives each chunk its kind and heading path;
  - converts `superseded_by` to index doc_ids;
  - `evaluate_checks` holds the VERIFY logic.
- **`backend/app/rag/pipeline.py`:**
  - `index_documents(..., tag_input=None)`. With `tag_input`, every chunk is tagged and validated,
    and a chunk whose tags do not validate stops the build;
  - the manifest gets an `applicability` block. It is `None` for untagged indexes, and nothing else
    changes for them.
- **`backend/app/database.py`:** the Qdrant payload adds the `app_*` keys when a chunk has
  `applicability`.
- **`metadata_extraction/applicability_extractor.py`:**
  - `tag_chunks(chunks, cache_path=None)` with the `LLM_CUE` filter and an on-disk cache keyed by

  - the Ollama call uses `think="off"`.
- **`scripts/ingest_snapshot.py` (new):** `--dry-run`, BUILD, VERIFY, `--publish`, `--no-llm` and
  `--force`.
  - It refuses `--index-id default`, and refuses an existing id unless `--force`.
  - It checks that the Ollama model is installed before BUILD.

## Deviations from the spec

- **Table rows are never split by a section cut, but overlap is lost there.** Sections are cut at
  span boundaries before 320 tokens, rather than changing the chunker. Chunk overlap (48) therefore
  only applies inside a single span longer than 320 tokens; a section cut has no overlap.
- **Snapshot doc_ids are replaced in the index.** The index's doc_id is `make_doc_id(source_uri)`,
  as for every other index. The snapshot's own doc_id is kept as `snapshot_doc_id`.
