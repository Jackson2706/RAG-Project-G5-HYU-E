# T09b result

Owner: Codex. Phase: P4. Date: 2026-11-10.

## What changed

- LLM fallback errors now have their own `llm_errors` count. Exceptions from model resolution or
  completion produce no tags, do not enter the cache, and do not count as rejections.
- The tag cache key now hashes the resolved model digest, `TAG_PROMPT_VERSION`, and the chunk-text
  hash with newline separators. Model resolution happens once per tagging run before the first
  cache lookup. A missing digest is an LLM error.
- Auxiliary tagging fixes temperature at 0, seed at 42, `num_ctx` at 4096, and thinking at off.
  The manifest records these values with the model, digest, prompt version, and cache path. A
  rules-only run does not resolve an Ollama model and records `llm.enabled` as false.
- Applicability manifest counts now include `tagged_by_rule`, `tagged_by_llm`, rejection reasons
  and total, `llm_errors`, `llm_called`, `llm_cache_hits`, and `unconditioned`. VERIFY copies these
  counts into its JSON and Markdown reports. Rejections remain report-only.
- `SpanInfo` carries snapshot offsets. The pipeline stores the covered offsets as `source_spans` on
  each MongoDB chunk. VERIFY reloads `documents.jsonl`, reconstructs whole-span text exactly, and
  accepts a substring only for a chunk covered by one long span. It reports the mismatch count and
  the first five chunk IDs.
- VERIFY now requires `llm_errors == 0` and `span_text_mismatches == 0`. Its token check counts the
  same section header plus chunk text passed to the embedder, including the two BGE special tokens.
- The offset test compares every lookup slice with the expected text in order using equality.
  Cache identity, failed calls, source-span matching, and the new VERIFY checks have unit tests.
- The AAES Index section documents the cache identity, manifest fields, source spans, and publish
  conditions.
