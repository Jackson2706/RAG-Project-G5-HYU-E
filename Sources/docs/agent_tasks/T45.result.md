# T45 result: component tables from saved Stage B traces

`Sources/scripts/deck_v5.py` now has a `components --runs <run_id,...> --splits dev,dev2` subcommand.
It writes `components_v5.csv` and `components_v5.json` under `Report/slides/deck_v4/aaes_plus/`, with
one row per A0_AAES or planned AP_* preset, pooling every case in the requested splits. The JSON is a
list of the same rows as the CSV. Definitions and zero-denominator behavior are in the
`components_table` docstring.

- Step 3 detail hit uses `clarify_attribute`, falling back to the first trace `branch_attributes` entry.
  The denominator includes only cases with a chosen detail and nonempty label `branch_attributes`.
  `step3_detail_cases`, `step3_detail_hits`, and `step3_detail_hit_rate` expose the denominator, hits,
  and their ratio.
- Step 3 split prediction is positive when trace branch attributes are nonempty or the saved action is
  CLARIFY/CONDITIONAL. Gold is positive for expected clarify/conditional_answer. The row records TP,
  FP, FN, precision, recall, and F1. This prediction does not use the v2 reply type.
- Step 4 compares cached v2 reply types against `expected_behavior`. Each of the sixteen
  `step4_expected_<gold>__predicted_<v2>` columns is a confusion count, including zeros. The row also
  records correct replies and accuracy. Acceptable alternative behaviors do not count as exact matches.

`components` and `ablation` share T44b's coverage check. Every requested case needs a completed record
and a matching v2 label for A0_AAES and every planned AP_* preset. Missing coverage raises an error
listing presets and split/case ids before either export is written. Other presets are excluded from the
component table. Held-out splits are rejected before labels are loaded. No labels or model calls are added.
Undefined rates are JSON null or blank CSV cells; F1 is zero for FP-only/FN-only cases and undefined
when TP=FP=FN=0.

Validation in the existing RAG environment:

- Deck script tests: 69 passed, with hand-computed detail, split, and confusion scores; separate
  trace-action and v2 predictions; missing/null trace fields; zero denominators; CSV/JSON agreement;
  multiple runs and splits; and rejection of incomplete inputs without overwriting exports.
- Full evaluation tests: 158 passed.
- Backend tests, including registry checks: 327 passed. Existing mongomock and Qdrant warnings remain.
- Runner `--suite all --dry-run`: exit 0, with 108 tasks planned. MongoDB, Qdrant, and Ollama were
  unreachable; affected model tasks were blocked. No evaluation ran.
- Read-only saved-run check: `deck4-dev`, split dev, produced rows in memory for 15 presets with
  47 cases each; each confusion matrix summed to its case count. The dev+dev2 check rejected the
  same run because its dev2 coverage of records with matching v2 labels is incomplete.
- CLI help and `git diff --check` passed.
