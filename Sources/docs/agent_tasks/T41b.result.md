# T41b result: retention and deletion across trace stores

Implemented by Codex on 2026-11-20.

## Changes

`Database.trace_databases()` reuses `list_index_revisions()` and `for_index()` to find the default store and every index revision with a manifest, including tagged HYU and smoke revisions. Startup calls the existing index setup for each store, so TTL creation, expiry updates through `collMod`, and legacy-date backfill apply to all of them.

`GET /api/traces` returns the summed `count` plus `stores`, a mapping from index ID to its trace count. `DELETE /api/traces` deletes traces in each discovered store and returns the summed `deleted` count. Store discovery runs on each request, so counting and deletion include revisions added after startup. The existing localhost check and response fields used by the Help panel remain compatible.

The mongomock tests cover the default store, a tagged revision, and a smoke revision. They check expiry indexes and backfill at startup, expiration of old traces, total and per-store counts, deletion across stores, preservation of documents/chunks/manifests/indexes, and rejection of remote clients even with a forwarded localhost header. A synthetic-fixture `/api/chat` test runs the listed B0 preset with mock Ollama on a tagged index revision created after startup, then verifies its trace is counted and deleted without restarting.

Updated `Report/slides/deck_v4/privacy_check.md` to describe all stores and the API response. Reviewed the changed prose with Humanizer against `Report/voice_sample.md`.

## Limits and scope

Live MongoDB TTL scheduling and live `collMod` were not checked. Mongomock exercises expiration; the existing `collMod` test mocks the unsupported command and checks its arguments. MongoDB removes expired traces asynchronously. Legacy rows with unparseable dates remain deletable but cannot expire automatically.

TTL setup runs at backend startup. A revision added during a running session is immediately included in counting and deletion, and receives its TTL setup on the next startup. Concurrent chat requests can save traces after deletion; counting and deletion across stores are not atomic. Database errors propagate rather than returning a false success count.

`GET /api/traces/{request_id}` still reads the default store. Databases without an index manifest, other than the default store, are outside the app's index discovery. Unrelated databases are not cleared.

Only T41b's allowed repository paths were edited: `database.py`, `api.py`, `main.py`, `test_trace_expiry.py`, the privacy check, and this result note. Existing unrelated worktree changes were left intact. `Report/project/STATUS.md` and `Report/ai_use_statement.md` were excluded by the explicit allowlist. No collections were dropped, and no commit or push was made. No crawl, download, live index build, evaluation run, or screenshot was performed.

## Human commands

No additional test command is required. Restart a running backend to apply startup retention setup to existing stores. With MongoDB and Qdrant already running, the backend command from the repository root is:

```sh
conda activate RAG
(cd Sources/backend && python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000)
```

To repeat the checks from the repository root:

```sh
conda activate RAG
(cd Sources/backend && PYTHONDONTWRITEBYTECODE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 pytest -q -p no:cacheprovider)
(cd Sources && PYTHONDONTWRITEBYTECODE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 pytest -q -p no:cacheprovider evaluation/tests)
(cd Sources/frontend && npm run typecheck && npm test -- --cache=false)
(cd Sources/backend && PYTHONDONTWRITEBYTECODE=1 python -c 'from app.rag.registry import check_registry; check_registry()')
(cd Sources && PYTHONDONTWRITEBYTECODE=1 HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python -m evaluation.runner --suite all --dry-run)
```
