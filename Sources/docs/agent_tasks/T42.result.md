# T42 result: AAES+ both-mode profile and branch fixes

## Changes

Step 1 now classifies current-question rule quotes as `self`, `hypothetical`, or `mention`
through the pure `aaes_llm.rule_kind` function, with doctests. Hypothetical cues take
precedence within their sentence. Repeated campus quotes follow the existing campus rule's
selected match.

In `both` mode, hypothetical and mentioned rule values require matching, valid,
quote-verified LLM confirmation. Otherwise the attribute becomes missing and scope defaults
apply. This also holds for malformed LLM JSON and for a conflicting LLM value. Self and
earlier-turn rule values retain their priority. Dropped values appear in
`trace_details["dropped_unconfirmed"]`.

Step 3 now makes one `SAME` call when all evidence sets have answers, at least two lexical
groups remain, and their numeric-token sets match. The call receives the question and one
answer per group. Valid agreement produces `ANSWER` with reason `same_meaning`.
Disagreement or invalid JSON keeps the rules' split; invalid output increments the `same`
fallback count. Differing numbers, `NONE`, lexical agreement, and extraction limits skip
the call. `trace_details["same_check"]` records the result or skip reason.

The new fake-LLM regressions cover the requested TOPIK probe, self and bare campus values,
confirmation validation, scope defaults, semantic agreement and disagreement, numeric and
`NONE` guards, invalid comparison output, repeated lexical groups, and unchanged rules/LLM
mode paths. The AAES+ section of `aaes_spec.md` documents the behaviour.

T42 edits are confined to its six allowed paths. `aaes.py`, presets, registry, labels,
evaluators, and `Report/` were not edited for T42. Other task changes appeared in the shared
working tree during validation and were left untouched. No commit or push was made.
