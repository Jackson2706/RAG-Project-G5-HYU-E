# T10g result: cue-designed test-100 audit

## What changed

- Added the `cue` sampling design for test-100. It assigns each eligible chunk to the first matching
  visa, student-type, degree, or `none` cue within its text, title, and heading path. Predicted tags
  are not used.
- Added repeatable `--min-cue CUE=N` arguments. Minimums are allocated across buckets in proportion
  to their populations, with at least 30% ERICA chunks per stratum when enough are available. The
  remaining places are allocated over the remaining bucket-by-cue populations.
- Added the stratum, `N_h`, and `n_h` to `sample_meta.json`, plus an assertion that the selected IDs
  do not overlap either exclusion file. The sample command prints the achieved count for every cue.
- Added inverse-probability scoring with `w = N_h / n_h`. Cue-designed TP, FP, FN, coverage,
  resolved precision and recall, strict recall, and unknown-condition share are design weighted.
  Wilson intervals use the Kish effective sample size of the units in each denominator. Reports
  retain the unweighted sample values next to the weighted estimates. Samples without a recorded
  design keep the earlier bucket-weighted method.
- Added raw degree-level FP and FN counts for applicant-tagged chunks and their design-weighted
  shares of all degree-level FP or FN units.
- Extended `report --side-by-side` to two or more folders with matching `--label` arguments. The
  final folder is marked as the gate sample.
- Updated the Tag audit section of `Sources/docs/aaes_spec.md` and added offline synthetic tests for
  cue minimums, seeded selection, two exclusions, cue precedence, hand-computed two-stratum scores
  and Kish intervals, applicant errors, and a three-folder report.

## Test-100 command sequence

Run from `Sources/` when the r5 audit starts. The first two metadata files contain the 150 dev-150
IDs and the 100 dev-100 IDs. The sample command asserts that test-100 contains none of them.

```bash
python -m labeling.auto_audit sample \
  --index-id hyu_20261110_97dc1269_r5 \
  --design cue \
  --n 100 \
  --min-cue visa=20 \
  --min-cue student_type=20 \
  --min-cue degree=20 \
  --exclude ../Report/results/tag_audit/hyu_20261110_97dc1269_r3/auto/sample_meta.json \
  --exclude ../Report/results/tag_audit/hyu_20261110_97dc1269_r4/fresh/sample_meta.json \
  --out test-100

# Blindly annotate test-100/blind_inputs.jsonl under the audit rules and write:
# ../Report/results/tag_audit/hyu_20261110_97dc1269_r5/test-100/reference.jsonl

python -m labeling.auto_audit compare \
  --index-id hyu_20261110_97dc1269_r5 \
  --reference ../Report/results/tag_audit/hyu_20261110_97dc1269_r5/test-100/reference.jsonl \
  --out test-100

# Review test-100/disagreements.jsonl without the side key or system output and write:
# ../Report/results/tag_audit/hyu_20261110_97dc1269_r5/test-100/decisions.jsonl

python -m labeling.auto_audit finalize \
  --index-id hyu_20261110_97dc1269_r5 \
  --reference ../Report/results/tag_audit/hyu_20261110_97dc1269_r5/test-100/reference.jsonl \
  --decisions ../Report/results/tag_audit/hyu_20261110_97dc1269_r5/test-100/decisions.jsonl \
  --out test-100

python -m labeling.auto_audit report \
  --side-by-side \
    ../Report/results/tag_audit/hyu_20261110_97dc1269_r4/reuse_r3 \
    ../Report/results/tag_audit/hyu_20261110_97dc1269_r4/fresh \
    ../Report/results/tag_audit/hyu_20261110_97dc1269_r5/test-100 \
  --label dev-150 \
  --label dev-100 \
  --label test-100 \
  --to ../Report/results/tag_audit/hyu_20261110_97dc1269_r5/g2b_three_way.md
```

The sample output must show at least 20 chunks in each requested cue. That buffer targets at least
15 reference occurrences for degree level, student type, and visa. A text cue is only a proxy: the
blind reference determines whether the attribute actually occurs, so 20 cue matches do not
guarantee 15 annotated occurrences.
