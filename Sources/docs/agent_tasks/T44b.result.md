# T44b result: complete coverage before selection

Codex completed both review fixes in `Sources/scripts/deck_v5.py` and added synthetic regression cases in
`Sources/evaluation/tests/test_deck_v5.py`.

`ablation` checks every case in the requested dev splits before writing outputs. A0_AAES and every planned AP_*
candidate must each have a completed record and a matching v2 label. Errors list every affected preset and its
missing split/case ids. Missing raw files, failed records, absent labels and stale reply hashes fail this check.

`select` reads the source runs and splits saved in `selection.json`, repeats the coverage check, and checks the CSV
against summaries recomputed from those sources before writing a selection. It preserves that provenance for later
calls. Failed validation leaves an existing selection unchanged.

Expected presets come from the union of `run_manifest.json` tasks, its session tasks, and `status.json` keys for the
requested splits. Raw files cannot define the expected preset set. `heldout` and `judge-items` share the balance check:
missing records or matching v2 labels drop a case across all planned presets, including presets omitted from the judge
export arguments. A planned preset with no completed records in any requested split raises an error naming it.
Held-out drops remain in `hypotheses.json`; judge exports record theirs in `heldout/judge/coverage.json` under
`dropped_unbalanced`.
