## LLM fallback boundary

The LLM is called only when rules produce no vocabulary constraint. It is left to handle explicit
applicability wording that the conservative keyword tables do not recognize. It cannot override a
rule result. The parser accepts the first decodable JSON object, then drops unknown attributes,
out-of-vocabulary values, missing quotes and quotes not found verbatim in the chunk. Rejection
reasons and call metadata are stored in `trace_details`; bad output and call errors return no LLM
tags instead of raising.
