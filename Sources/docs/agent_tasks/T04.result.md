## Review (Claude Code)

Fixed directly (each under 20 lines, with a regression test):
- `crawler/tests/__init__.py` added. Plain `pytest -q crawler/tests` failed at collection
  (`No module named 'crawler'`); only `python -m pytest` worked.
- `run.py _fetch`: a network error after retries, or a redirect to another host, escaped the
  crawl loop, so the whole crawl ended without `crawl_report.json`. The URL is now recorded as
  `status: "error"` and the crawl continues.
- `extract.py extract_attachment`: pypdf errors (`PdfReadError`, `PdfStreamError`) and XML parse
  errors were not caught. One broken attachment stopped the crawl and every `--build-snapshot`.
  They now become `attachment_parse_error` warnings.
- `extract.py discover_attachments`: ERICA links were searched only in `#bo_v_con`, but gnuboard
  lists files in `#bo_v_file`. The search now covers `#bo_v`, as the spec says.
- `fetch.py _load_robots`: a 5xx on robots.txt now means disallow all (RFC 9309), not allow all.
- Removed the unused `doc_id()` alias and the unused `site_for_url` import.

Open risks for the trial crawl:
- ERICA `download.php` may need the session cookie set by viewing the post. A first run works,
  because one client keeps cookies. On `--resume`, an attachment fetched without its post may
  return an HTML error page, which now becomes a parse warning.
- With `--max-pages 30`, Seoul fetches mostly static pages, because the sitemap lists them before
  the notices.
- MinHash over long attachments may make `--build-snapshot` take a few minutes.
