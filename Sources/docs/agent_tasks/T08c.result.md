# T08c result

Owner: Codex. Phase: P4. Date: 2026-11-11.

## What changed

- The rule tagger now emits `korean_standard=pass|exempt|fail` and no longer stores the Korean
  Language Standards phrases as free-text requirements.
- `academic_status=applicant` is limited to admission-guide title patterns. A matching chunk must
  also mention an applicant, application, or admission. Acceptance guides and scholarship text do
  not gain the tag.
- A TOPIK condition joined by “or” to IELTS, TOEFL, TEPS, or English track within one sentence or
  line becomes two `any_of` sets. A valid certificate without a level maps to levels 1–6. The
  alternative attributes are removed from ordinary constraints.
- Preferred, additional-points, bonus, advantage, and optional wording is removed from rule and
  LLM constraints. Text-backed matches are retained as `preference:` requirements.
- Prompt v3 lists vocabulary v1, excludes `short_term`, includes `applicant` and
  `korean_standard`, and tells the model not to tag preferences. It does not ask for `any_of`.
- Postcheck p1 applies the approved fixed mappings, matches evidence after case and whitespace
  normalization, stores the exact chunk substring, drops every-value fields, and reports the fixed
  rejection labels. The manifest summary separates rejected chunks (`llm_rejected`) from rejected
  field units (`llm_rejected_fields_by_reason`).
- The LLM manifest block records `postcheck_version=p1` and `vocabulary_version=v1`. The dry run
  reports `any_of`, `korean_standard`, and `applicant` chunk counts. Frequency reporting counts
  Korean-standard values, alternative values, and the number of `any_of` sets.
- `aaes_spec.md` now documents vocabulary v1, alternative sets, preference handling, prompt v3,
  and postcheck p1.

## Protected-file conflicts and risks

- Three fixed-mapping cases call the local helper in `test_applicability.py` with
  `trace_details=...`, but that protected helper accepts only `chunk` and `llm`. Python raises
  `TypeError` before the extractor is called. The new direct tests cover all three mappings and
  pass without changing the protected test.
- The protected threshold test still expects `TOPIK level 5+ students get a bonus` to be a hard
  constraint. Amendment A17 and T08c require bonus wording to be a preference, so the
  implementation drops it and the new preference test passes.
- The protected every-value assertion expects the old prose reason. Postcheck p1 requires the fixed
  label `every_value`, which the implementation and summary use.
- `test_snapshot_index.py` compares the old LLM manifest dictionary for exact equality. T08c adds
  the required `postcheck_version` and `vocabulary_version`, so that stale assertion fails on the
  two required extra keys.
- T08c requires `extraction_method["any_of"] = "rule"`, but the protected
  `app/rag/applicability.py` validator rejects `any_of` as an unknown extraction-method field.
  The implementation records exact `any_of` evidence and treats it as rule-derived in summaries
  and frequency reports, but cannot store that method key without changing the protected file.
- `Report/project/STATUS.md` was not changed because T08c's allowed write paths exclude `Report/`.
  A concurrent workspace change to `Sources/labeling/tests/test_audit_tags.py` was left untouched.
