# T46 — Multi-provider model fallback

## Changed
- Local Ollama model selection now uses the installed model list; empty configuration uses the first installed model.
- Added `GROQ_CHAT_MODELS` and preserved `GROQ_CHAT_MODEL` for the Groq default model.
- Added the four configured Groq models: `qwen/qwen3.8-27b`, `llama-3.1-8b-instant`, `openai/gpt-oss-20b`, and `llama-3.3-70b-versatile`.
- Groq chat requests now try the next API key immediately, then the next configured model, for limit, invalid-key, unsupported-model, and server-retry statuses (401, 403, 429, 400, 404, 500, 502, 503, 504).
- Cloud Groq chat no longer requires a selected model to pass through the local Ollama installation check.
- Removed fixed Ollama model defaults from the applicability metadata and snapshot presets so an empty model uses the provider default.

## Verified
- `tests/test_ollama_and_api.py`: 15 passed.
- The fallback tests confirmed both model fallback after a 429 and API-key fallback from `key-one` to `key-two` in the same request.
- Local `/api/llm/models` currently lists the installed Ollama model `qwen3:4b`.

## Not checked
- Live Groq account model access and live rate-limit fallback.
- Full frontend and evaluation suites.

## Local fallback verified
- A live `/api/chat` request that deliberately selected `qwen/qwen3.8-27b` completed successfully.
- The backend returned `model=qwen3:4b`, because that is the currently installed Ollama model.
- Missing or stale Ollama model selections now fall back to the configured Ollama default, then the first installed model; they are no longer rejected with `model is not installed`.

## Human configuration
Set `LLM_PROVIDER=groq` and provide `GROQ_API_KEY` or a comma-separated `GROQ_API_KEYS` list. `GROQ_API_KEY` is included automatically as the first key. Optionally change `GROQ_CHAT_MODEL` and `GROQ_CHAT_MODELS` in `Sources/.env` or `Sources/backend/.env`. Restart the backend after changing provider settings.
