# T39 result: AAES+ fallback patch and continuation audit

## What changed

- Invalid or missing Step 2 LLM records now keep the corresponding rule label and overlap relevance.
- Step 2 `both` mode sends all top-six passages to Qwen for relevance, while known rule labels still win.
- Rejected Step 2 items are no longer counted again as missing.
- Step 3 answer grouping keeps different numeric values separate before applying the existing word-overlap rule.
- `deck_v4_aaes_plus.py step2` now scores invalid LLM items with the same rule fallback as the runtime.
- `deck_v4_aaes_plus.py probe` records dev/synthetic model-call traces without generation or heldout access.
- The local continuation audit is `Report/slides/deck_v4/aaes_plus/audit_2026-11-16.md`; raw probe details are in `patch_probe.json`.

The supplied `aaes_plus_handoff.zip`, `apply_fixes.py`, and `test_aaes_plus_patch.py` were not available on disk. The patch was reconstructed from the requested behavior. The added regression file uses the requested name, but its contents could differ from the missing attachment.

## Failures found and fixed

The first reconstructed regression run expected a matching campus-only rule tag to be `compatible`; the existing rule implementation calls it `unconditioned`. The test was corrected without changing that behavior. The second run found a source bug: one malformed item was counted as rejected and missing, so its fallback count was doubled. The runtime now counts it once.
